# Open questions and decisions

Each has a recommendation (★). Decide before the phase listed, and record the answer as an ADR when it's architectural.

| # | Question | Options | ★ Recommendation | Decide before |
|---|---|---|---|---|
| Q1 | **Product name** | Funes · Funes Memory · Funes Vault · Funes Mind · … | **Decided: Funes Vault.** "Funes" already means memory (Borges); "Vault" adds the missing half, control. It's different from the existing iPhone app "FUNES." (a 3D heritage archive), reuses the Funes Vault logo system, and the App Store subtitle carries "Private memory for AI agents". "Funes" stays as the short form in UI copy | Decided 2026-10-16 |
| Q2 | **Price** | Free & open source · Paid Mac app · Free Mac + paid iPhone · Free + paid "Pro" | **Free & open source for the preview**, like EK Bridge. Revisit at 1.0 if usage is real; a paid iPhone app is the cleanest later option | Phase 4 |
| Q3 | **License** | Apache-2.0 · MIT · source-available | **Decided: Apache-2.0**, matching EK Bridge and Funes Vault. `LICENSE` is in the repo from the first commit | Decided 2026-10-16 |
| Q4 | **Repository** | New repo · inside `funes-vault` | **Decided: new repo `bereciartua/funes-vault-app`.** `funes-vault` (the web version) stays as a historical artifact | Decided 2026-10-16 |
| Q5 | **Minimum macOS** | 14 (like EK Bridge) · 15 · 26 | **Decided: 15**: broad reach. Foundation Models features gated to 26+ | Decided 2026-10-16 |

| Q7 | **Encryption at rest** | FileVault only · SQLCipher with a Keychain key | **Decided by the user: FileVault only for v0.1, no SQLCipher.** SQLCipher adds a dependency and key handling for limited gain against the same-user threat model. | Q8 | **BridgeKit timing** | Copy now, extract later · Extract first · Tiered | **Decided: tiered.** Extract the protocol and security core now (EK Bridge adopts it first); copy UI pieces and extract after v0.1; Remote Access extracted for v0.1 as `BridgeKitRemote` ([ADR-0013](../architecture/decisions/0013-shared-bridgekit-core.md), amended by [ADR-0018](../architecture/decisions/0018-remote-access-in-v0.1.md)) | Decided 2026-10-16 |

| Q24 | **Push channel for iPhone approvals** | **CloudKit "doorbell"**: the Mac writes a record to the user's private database, and a subscription wakes the phone · **APNs through a small relay**: the Mac asks a relay holding the APNs key to send the push | **Either way, no memory text goes through Apple or a relay:** only "you have a request" and an opaque id. The phone fetches the details over the companion channel, and a notification service extension can word the alert on the phone. ★ **CloudKit first**: no server of ours (the relay would amend [ADR-0003](../architecture/decisions/0003-mac-is-the-only-source-of-truth.md)'s "no server of ours"; CloudKit amends only its "no CloudKit", for a doorbell with no data). Measure its delivery time early in Phase 5: if it can't usually beat the 45 s in-call wait, approvals still work through the 15-minute pending list, and a relay is the fallback. **Proposed as [ADR-0019](../architecture/decisions/0019-cloudkit-doorbell-for-iphone-approvals.md)**, which amends ADR-0003's "no CloudKit" for a doorbell with no data; the measurement ([spike](../../spikes/cloudkit-doorbell/README.md), [results](spike-results.md#q24-cloudkit-doorbell-delivery-time)) is waiting for the maintainer's iPhone | Phase 5 (before 5.6) |

- **Existing app:** an iPhone app called **"FUNES."** (AAANY Limited, funes.world; a 3D cultural-heritage archive, released Feb 2026) exists, which is why the store name is qualified as "Funes Vault".
