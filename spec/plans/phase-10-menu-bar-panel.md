# Phase 10: Menu bar panel

**Goal:** a click on the menu bar icon answers three questions at a glance: what waits for me, can agents reach my vault, and what happened lately. It also lets you remember or search without opening the window. Every control says what it does.

**Duration:** about 2 weekends. **Depends on:** nothing unfinished (Phase 9's search answers are in). **Decision:** [ADR-0029](../architecture/decisions/0029-menu-bar-panel.md). **Specs:** [UX: Mac ▸ Menu bar](../product/04-ux-mac.md#menu-bar), requirements FR-G-01, FR-A-11, FR-D-05, FR-H-07, [glossary](../product/06-glossary.md#the-app-its-server-and-pause).

**Order:** 10.0 → 10.1 → 10.2 → 10.3, 10.4 and 10.5 (any order) → 10.6. Everything lands in one PR with the spec, as `feature/menu-bar-panel`.

## 10.0 Spike: closing a non-activating panel · ¼ weekend
Throwaway code (a scratch target or a branch of the app that isn't merged) that proves the panel's mechanics before anything else is built. Record what works in this plan.
- [x] A borderless non-activating `NSPanel` that becomes key for a text field, under the status item, while another app stays active (check with TextEdit frontmost).
- [x] **It closes on:** a click outside (another app, the desktop, the menu bar); a second click on the status item (no reopen from the same click); Esc; ⌘⇥ to another app; a Space or full-screen change; the screen locking.
- [x] **It doesn't close** while its own pause menu, ⋯ menu or the Remote Access confirmation is up, or while the dictation permission prompt shows.
- [x] **The field:** typing, IME input (Japanese, accents) and the system's dictation work; Return reaches the field; VoiceOver lands in it.
- [x] Note which signals were needed (workspace activation notifications, key-window changes, event monitors) and update the UX spec if a closing rule can't be met.

*Results (2026-10-30, macOS 27.0.1, a scratch AppKit app driven by synthetic events, not merged):*
- *A `[.nonactivatingPanel, .borderless]` panel with `canBecomeKey` true at `.popUpMenu` level, opened with `makeKeyAndOrderFront`, takes typing while TextEdit stays the frontmost app (`NSWorkspace.frontmostApplication` stays TextEdit; TextEdit keeps the menu bar). Accented and Japanese text typed into its field arrived intact, and Return reached the field.*
- *Closed, each driven and logged: a click in TextEdit's window and on TextEdit's menu in the menu bar (a global mouse monitor); another app activating, by AppleScript and by a real ⌘⇥ with the Command key held (`NSWorkspace.didActivateApplicationNotification`); Esc (`cancelOperation`); a second real click on the icon.*
- ***The icon's own click reaches the global monitor too** on this macOS: without a guard the second click closed the panel and the same click reopened it. The monitor ignores clicks inside the status button's screen frame, and the button's action toggles. With that, a second click closes it and nothing reopens.*
- *Its own `NSMenu` (`popUp(positioning:at:in:)`) doesn't close it: the panel stays key while the menu is up, and Esc closes only the menu. A click in another app while the menu is up closes the menu and then the panel, since it's a click outside; a "hold" counter keeps the panel open for exactly the menu's lifetime. The Remote Access question (`NSAlert.runModal`, which activates Funes) is held the same way; the app that was frontmost is activated again afterwards and its activation doesn't close the panel.*
- *Not driven (they'd disturb the Mac in use), so wired to their documented signals and listed in `docs/TESTING.md`'s manual check: a Space or full-screen change (`activeSpaceDidChangeNotification`), the screen locking (`com.apple.screenIsLocked`, `sessionDidResignActiveNotification`), sleep (`willSleepNotification`, `screensDidSleepNotification`), real IME composition, the system's dictation, the dictation permission prompt (the panel holds while dictation is starting) and VoiceOver. No closing rule needed a change to the UX spec.*

## 10.1 Last 24 hours read · ¼ weekend
- [x] **`VaultStore.recentPulse(now:calendar:)`** in FunesCore (`Store/OverviewStore.swift`, beside `overview`): 24 hourly buckets ending with the current hour. Each bucket holds new memories by source (`memory.created_at`, `memory.source`, the iPhone rule of ADR-0025), memories delivered by agent (`disclosure.delivered_at` joined to `disclosure_item`) and requests refused (`disclosure` with status `denied`). Plus the totals and the agents' display names. It reuses `VaultOverview.Bucket` (its `date` is the hour's start) and adds no table. Hours follow the calendar's time zone.
- [x] **Tests:** buckets and totals on a fixture; an empty vault; a memory at 09:59:59 and one at 10:00:00; a daylight-saving change (23 or 25 clock hours still make 24 buckets of an hour each); no text or title anywhere in the result (encode it and search for the fixture's sentinel strings).
- [x] **Budget:** under 20 ms on the 10,000-memory benchmark vault, in the existing `FUNES_OVERVIEW_BENCHMARK=1` check. If it misses, say so here before adding an index. *(1.6 ms CPU, best of 7, 1.9 ms median; no index added.)*
- [x] **A repeated hour** when clocks go back is two buckets; each bucket carries its start as an instant, so the UI can label it with its zone.

## 10.2 The panel shell · ½ weekend
- [x] **`MenuBarPanel`** (`Apps/FunesMac/MenuBar/`): a borderless, non-activating `NSPanel` that can become key, hosting SwiftUI, 350 pt wide, positioned under the status item's button (and kept on the screen that has it). It closes on what 10.0 proved: Esc, a click outside, another click on the icon, another app activating, a Space change and the screen locking. The old menu's items and `menuNeedsUpdate` go away. The icon's tooltip and accessibility label stay, with the new wording of [UX: Menu bar](../product/04-ux-mac.md#menu-bar).
- [x] **The icon's "can't connect" state** in `MenuBarIcon` and `AppModel.iconState`: `mcpStatus == .failed` draws the warning badge instead of the slash.
- [x] **Appearance** follows `NSApp.appearance` (FR-G-06); the material is the menu bar's (`NSVisualEffectView` `.menu` or `.popover`, whichever matches macOS 26's extras best, checked on screen). *(`.menu`, with 12 pt continuous corners, checked on macOS 27 beside Control Center's panel.)*
- [x] **Focus and keys:** the frontmost app stays active while the panel is key (a manual check, from 10.0); the field has the initial focus; Tab order and the key table of [UX: Keys in the panel](../product/04-ux-mac.md#keys-in-the-panel); ⌘O, ⌘, and ⌘Q work while it's key. - [x] **Height:** sections keep their size and the area under the field scrolls, as the UX spec says. A UI-review snapshot with the most the panel can hold, at 350 pt, on macOS 15 and 26. *(`menubar-panel-full`, captured on macOS 27 only: this Mac has neither 15 nor 26. Run `sh scripts/ui_snapshots.sh` on each before the release.)*
- [x] **VoiceOver:** the panel announces "Funes Vault" and what waits when it opens.

## 10.3 Waiting for you and the switches · ½ weekend
- [x] **`WaitingItems`**, a small model (with tests) that merges three sources into cards: `services.approvals.queue.items` in the queue's order; `model.signIns` (one at a time); and `model.pending` with status `needsApproval`, soonest expiry first, leaving out any request already in the queue (matched by request id: `DisclosureService.pendingRequests` also returns the one on screen). At most 3 cards, then "2 more waiting" with **Show All Pending Requests** while some of the rest are Pending requests. It also names the card the Review Request shortcut would review, and Review Request uses the same answer, so the label and the shortcut never disagree. Tests: a live request timing out into Pending (one card throughout), one answered on the iPhone (its card goes), sign-in plus queue ordering, more than 3.
- [x] **Review routes:**
  - a live queue item: `approvals.queue.select(id)`, then the approvals' review (bring forward, key);
  - a Pending request: `model.openPendingRequest(id)`, which refreshes it;
  - a sign-in: a new route that brings `SignInPanelController`'s panel forward, key.
  A test that the key press choosing Review doesn't answer the panel it opens (each panel's arming delay, and the sign-in's missing Return key). A test that the card view can't reach `answer`, `withdraw` or any sign-in decision. *(`WaitingItems.Route` has only the three routes, and `MenuBarPanelTests.aCardOnlyRoutes` checks them and the approval panel's 0.6 s arming; the sign-in panel's Allow has no key equivalent and arms after 1 s, unchanged. `scripts/test.sh` fails if `MenuBar/`, `MenuBarPanel.swift` or `PanelField.swift` ever call `withdraw`, `answer`, `approve`, `deny` or a sign-in decision.)*
- [x] **Agents tile:** every state in the UX table, in its order, from `preferences.mcpEnabled`, `mcpStatus`, `pausedUntil` and `agents.count` ("No agents yet" with **Add Agent…** opening `wantsAddAgent`). Turning it off shows the three lengths (`FunesPause.Duration`) and calls `model.pause(_:)`; turning it on calls `model.resume()`. The paused line with **Resume**. **Fix…** and **Turn On…** open Settings ▸ Connections. A tap on the tile opens Agents. *(Settings ▸ MCP until the settings redesign adds Connections; the UX spec says so. `AgentsTile` in BridgeUI, tested.)*
- [x] **Remote Access tile:** every state in the UX table, in its order, from `remoteAccess`: "not set up" by the same rule as `RemoteAccessPage.mode`'s introduction (move that rule into the controller so both use it); `enabled`; the listener's real status (not listening while the agent server is off or failed); `tunnelDown`; `offAt` ("On · until 18:00"); `cloudAgents`. The switch shows whenever it's enabled. Turning it on goes through `RemoteAccessController`'s existing confirmation; turning it off calls `remoteAccess.apply(false)` at once; the automatic turn-off updates the tile at once. **Set Up…** and a tap on the tile open Remote Access.
- [x] **Countdowns** tick each second while the panel is open (a timer only while it shows), with VoiceOver's "41 seconds left" wording as the panels use.

## 10.4 The field · ½ weekend

The capture box keeps its behavior. ⏎ saves, ⇧⏎ is a new line, and the field grows to 4 lines, then scrolls.
- [x] **Dictation** on macOS 26 and later with `Dictation.swift`, stopped (as `stopDictation` does for the box) on save, ⌘⏎, Esc and closing, with late words dropped.
