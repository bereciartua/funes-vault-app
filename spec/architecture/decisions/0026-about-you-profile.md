# ADR-0026: A small "About you" profile beside the vault, shared per agent and per field with memory requests

**Status:** Accepted · 2026-10-26 · **Amends** [access policy](../../domain/access-policy.md) (principle 3, a new §3.10, test vectors T36–T46), [MCP server §5–6.2](../mcp-server.md#5-server-instructions-serverinstructions) (the instructions and `request_memory`'s output), [companion protocol §4](../companion-protocol.md#4-methods) (`status.get`), [storage](../storage.md) (`v6_profile`)

**Context.**
- **Funes doesn't know who you are.** Home greets you with the first word of the macOS account's full name ([UX: Mac ▸ Home](../../product/04-ux-mac.md#home)). That name is often a username: the author's Mac says "Good afternoon, mib." The iPhone's Home shows no name at all.
- **Agents don't either.** An agent learns your name only if a memory happens to contain it and its task happens to retrieve it. Your name, the languages you write in and where you are come up in nearly every task, and they're the first thing each assistant builds its own profile from. Funes exists so you don't have to tell each assistant again ([vision](../../product/01-vision.md)).
- **Memories are the wrong container for these.** They work as memories only by accident of retrieval. They'd also be exposed to the processing that keeps memories tidy: the daily tidy-up may merge, reword or archive them, and splitting may cut "Martin Bereciartua, he/him, Lisbon" into pieces ([ADR-0020](0020-atomic-extraction-for-every-source.md), [ADR-0021](0021-daily-tidy-up.md)). Your name isn't a fact to reconcile.

**Decision.**
1. **A profile, one per vault, every field optional** (the [domain model's Profile](../../domain/domain-model.md#profile)): given name, family name, what Funes should call you, pronouns, languages, location, time zone (automatic by default, following the Mac) and occupation. It is stored in `vault.sqlite` next to the memories, but it isn't a memory: it has no categories, sensitivity, kind, versions in disclosures or provenance, and memory processing never reads or changes it. It has eight fields in six groups, and it stays that small. Anything richer about you is a memory.
2. **Edited on the Mac,** in Settings ▸ About You, and offered on the first page of the seed questions. It's prefilled from the macOS account only as a suggestion the user confirms, never saved silently. The secret scanner checks every field on save.
3. **Shared per agent and per field, decided in advance.** Each agent's access gains a set of **profile fields** it may see: `name`, `pronouns`, `languages`, `location`, `time_zone`, `occupation`. A new agent gets `name`; the rest start off. They're toggled in the agent's Access tab. Changing them is an access change: it bumps the agent's revision, so pending approvals are invalidated as for any other access change.
4. **Delivered with `request_memory`, not by a tool of its own.** Every `request_memory` response that passes the agent gate (G1–G4: Funes and the agent not paused, access not expired, Read granted) carries a `profile` object with the agent's shared fields that have a value, whatever retrieval and the decision say: delivered, fulfilled, waiting for approval, or denied for having nothing relevant or nothing allowed. Gate denials carry none. The rules are in [access policy §3.10](../../domain/access-policy.md#310-the-profile).
5. **The user sees what goes.** The Share panel says what the agent also got ("Claude Code also has your name and pronouns, as set in its Access."). Activity records which fields went (names only, never the values). Settings ▸ About You shows how many agents see each field.
6. **The iPhone greets you by name.** `status.get` returns the name Funes calls you (or nothing). The phone keeps the last one with its pairing, for Home's title while the Mac is away, and deletes it on unpair and revocation. Editing the profile on the iPhone comes later.

**Consequences.**
- **Principle 3 of the access policy gets one named exception.** A request waiting for approval returns no memory text, but it does return the profile fields the user chose to share with that agent. The consent for these is given in the access editor, field by field and agent by agent, like turning off ask before sharing, only for a few short facts.
- **Agents get your name with no extra call** and no new tool to discover. An agent that never calls `request_memory` never gets it. That's fine: calling it is how an agent asks for context.
- **The profile isn't part of a request's snapshot.** Editing it doesn't invalidate approvals; each response carries the profile as it is at that moment.
- **The result-size reserve grows by the profile's actual size** (at most about 700 characters), so a bundle never overflows the 200,000-byte limit. The profile doesn't count against `max_tokens`.
- **A new schema migration**, `v6_profile`: the `profile` table and `access_profile_field`, with `name` for every existing agent.
- **Not sent to AI model providers** in this change: classification, splitting and the tidy-up prompts don't include it. If a later version wants the name in prompts (to resolve "I" in a capture, say), it's a decision of its own, under the cloud limit.
- **Exported and restored** with a Funes export (`profile`, optional in `funesvault.export.v1`); Erase All Data erases it.

**Alternatives considered.**
- **Memories in a built-in "About me" category:** reuses the access rules, panels and iPhone screens for free. But a name would only reach agents when retrieval matches it, it would sit in the Share panel as one more memory to tick, and the tidy-up and splitting would treat it like any other text. Rejected.
- **A `get_profile` tool:** clearer as a contract, but agents would have to know to call it, and the clients that load tools lazily rarely would. One more tool also means one more line in every agent's tool list. Rejected for now; it can be added later beside §3.10 without changing the rules.
- **In the MCP server instructions** sent at `initialize`: every client would see it before any check. It would be stale for as long as the client caches it, sent while Funes or the agent is paused, and never logged. Rejected.
- **Asking each time, in the Share panel:** consistent with principle 3, but a panel for "may Cursor know your name?" on every request is the fatigue the allow window and the strong-match ticks exist to avoid. The field toggles are that question, asked once.
- **Prefilling from the Contacts "Me" card:** a better source than the account name, but it costs a Contacts permission prompt for a few fields the user can type in a few seconds. Not done.
- **Only first and last name:** too little for agents (language and location come up constantly) and wrong for many names. Given, family and "what should Funes call you" cover name order, nicknames and people who go by their middle name.
