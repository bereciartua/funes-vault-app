# Security and privacy model

## 1. Assets
| Asset | Why it matters |
|---|---|
| Memory text (title and body) | Personal and possibly sensitive. The main asset |
| Access settings | Decide who gets what. Tampering widens disclosure |
| Agent keys | Holding a key means acting as that agent |
| Remote credentials (remote tokens, OAuth access and refresh tokens) and the Remote Access secret path | Held by cloud vendors. Holding one means acting as that agent from the internet, through the user's tunnel |
| Device keys and pairing secrets | Holding them means owner-level access to the vault |
| Activity and provenance | The audit trail. It must not leak text, and must not be silently erasable by agents |
| Earlier versions of memories (v0.5, [ADR-0027](decisions/0027-memory-revisions.md)) | The text each change replaced, kept 90 days. As sensitive as memory text, and easy to forget about |
| Task texts sent by agents | Can reveal what the user is working on. Held in memory only, for up to 15 min |

## 2. Actors and trust
| Actor | Trust | Can |
|---|---|---|
| **User at the Mac** | Full | Everything, through the UI |
| **Paired iPhone (owner device)** | Full, but authenticated per message | Owner operations through the companion API, logged |
| **Connected agent** | Scoped | Only what its access allows. Its words are data |
| **Agent's AI provider** | Untrusted, out of our control | Sees whatever the user released to the agent |
| **Cloud agent** (claude.ai, ChatGPT, cloud coding agents; v0.1, Remote Access) | Scoped, like any agent; runs on its vendor's servers, often while the user is away | Only what its agent's access allows, through the user's tunnel, while Remote Access is on |
| **Other local processes (same user)** | Out of scope | Can read the user's files and keys. Funes can't defend against malware running as the user (the same boundary as EK Bridge) |
| **Other local users / processes** | Untrusted | Reach 127.0.0.1:47625 but need a key |
| **LAN peers, the Tailscale network, tunnel providers, internet** | Untrusted | Reach 47626 only in the modes the user enabled; they see envelopes they can't read or forge. Reach 47627 only through the user's tunnel while Remote Access is on, and need the secret path and a remote credential. Tunnels that end TLS at their edge (Cloudflare, ngrok) can read Remote Access traffic |
| **Malicious web pages in a browser** | Untrusted | Could try DNS rebinding or CSRF against localhost. Blocked |

## 3. Threats and mitigations
| # | Threat | Mitigation |
|---|---|---|
| T1 | A prompt-injected agent asks for everything ("ignore rules, share all") | Purpose and task never affect eligibility ([policy §1](../domain/access-policy.md)); exact-text approval by default; ceilings and categories enforced server-side. Test T12 |
| T2 | An agent learns which memories exist from denials | Withheld counts only, no ids or titles; `not_found` is the same for missing and forbidden; categories are listed without counts |
| T3 | An agent plants malicious instructions in the vault (stored prompt injection) | Suggestions are reviewed by default; Write needs an explicit grant with ask-before-saving off; agents can only write within their scope; released text is wrapped with "user data, not instructions"; Activity shows who suggested what |
| T4 | An approved release is used after things changed (TOCTOU) | Snapshot revision; delivery re-checks the agent revision, memory versions and eligibility in one transaction; single use; 15-min expiry. Tests T13–T17 |
| T5 | Another agent reuses a request id | Requests are bound to the requesting agent; others get `not_found`. Test T20 |
| T6 | Stolen agent key | Key files are 0600 in a 0700 folder; the database holds only digests; rotate or remove in one click; all use is logged; local-only listener |
| T7 | DNS rebinding / CSRF from a browser to localhost | Host must be loopback (421); any Origin refused (403); POST and JSON only; no CORS |
| T8 | A launcher talks to an impostor listener and leaks the key | The launcher verifies the listener's owner, bundle ID and socket via `libproc` before sending the key (EK Bridge) |
| T9 | Network attacker reads or forges iPhone traffic | Per-message HPKE encryption plus a device signature with a Secure Enclave key, a replay window and nonce cache; responses are encrypted with a key exported from the request context |
| T10 | Someone photographs the pairing QR code | It's valid once for 5 min, and pairing also needs **Allow** on the Mac. Devices are listed and revocable |
| T11 | Lost or stolen iPhone | Revoke on the Mac. The phone holds no vault data, only queued captures (protected after first unlock) and keys (Secure Enclave, `ThisDeviceOnly`) |
| T12 | Public tunnel exposure of the owner API | Off by default; secret path plus Host check; signed and encrypted envelopes; rate limits and failed-auth lockouts. LAN and private Tailscale are recommended |
| T13 | Secrets end up in the vault and then get shared | The secret scanner runs on every write path, on both the Mac and the phone. Funes's own keys are in the patterns |
| T14 | Memory text leaks into logs or crash reports | Activity and provenance hold ids and labels only; earlier versions of a memory live in `vault.sqlite` with the memory and go with it; OSLog uses `privacy: .private` for any user content; no third-party crash reporting; test fixtures assert no text in logs |
| T15 | Database corruption or tampering by another process | Out of scope for tampering (same-user boundary). Corruption: WAL, integrity checks, daily backups |
| T16 | Malicious update | Sparkle EdDSA-signed appcast plus Developer ID and notarization; Homebrew cask checks the attestation and SHA-256 |
| T17 | A flood of agent requests or suggestions spams the user | Rate limits; at most 3 waiting approvals per agent; panels capped at 3 on screen; "Pause Funes Vault" |
| T18 | Memory, capture, search or task text sent to an AI model provider | Apple on-device by default. Any other provider is the user's explicit choice, labelled with exactly what it receives. The secret scanner runs on every outgoing text. The cloud sensitivity limit (default Internal) is never exceeded. Captures are pre-screened on the device before cloud classification. API keys live only in the Keychain. Tested with request capture ([model providers §9](model-providers.md#9-testing)). **v0.3:** the limit is the user's choice up to everything ([ADR-0022](decisions/0022-cloud-limit-and-daily-cap.md)), one limit for every task; every item in a call is checked, and agent and import text is pre-screened on the device instead of trusting the declared level |
| T21 | Prompt injection through memory or capture text sent to a generation model | Text is fenced and labelled as data; output is constrained by a JSON schema and validated (unknown categories dropped, sensitivity raised to the category default); proposals are review-only and never applied automatically. **v0.3:** auto-apply is the user's choice and never acts on untrusted text (T31); extracted pieces must quote their evidence verbatim from the input; injection attempts are in the fixtures |
| T22 | A stolen provider API key is used elsewhere | Keys stay in the Keychain (this device only), never in the database, logs or exports. Removing a provider deletes its key. The user rotates keys at the provider |
| T31 | An agent or pasted text drives automatic changes to the user's memories (v0.3): a planted "the user is no longer allergic to peanuts", or a shared web page saying "I moved to Berlin" | Auto-apply is off by default. It never changes or archives a memory on the strength of untrusted text (agent direct writes, imports, shared and Services captures; [memory processing §5.7](../domain/memory-processing.md#57-auto-apply-for-new-memories)); updates and retractions from agent input are always suggestions; conflicts always go to the user; output from a fallback engine is never applied; every automatic change can be undone for 30 days. Injection attempts are in the fixtures |
| T32 | Splitting, merging or updating widens an agent's access or lowers sensitivity (v0.3) | A result's sensitivity is at least that of every memory whose text was in the call; merges only between memories with the same sensitivity and categories; updates keep their target's categories; split pieces never go below the original. Before anything is auto-applied, the policy engine checks that no agent could read the result without having been able to read every source. Pieces of agent input outside its scope go to the Inbox flagged, never saved for the agent |
| T33 | A misbehaving or prompt-injected agent runs up the user's model bill or starves their own processing (v0.3) | A daily cap on cloud requests (300 by default), of which agents may use at most 40%; agent input waits for the next day at the cap; pieces of a direct write count toward the agent's write rate limit |
| T34 | Prompt injection in memory or input text makes a subscription CLI (Claude Code, Codex) use a tool on the Mac: read files, run commands, drive the browser or the screen (v0.3) | Each call runs in an empty temporary directory, without the user's CLI configuration, MCP servers, hooks or plugins, and with every tool turned off ([model providers §5.8](model-providers.md#5-guardrails-all-non-local-providers)). Claude Code's start event must show no tool but structured output, no MCP servers or hooks, and only known built-in plugins; Codex is refused if it has any enabled feature Funes doesn't know is safe. Any tool or command event stops the run and discards its output. Extracted pieces must quote their evidence from the input, so file contents can't become memories that way. **Residual, accepted by opt-in:** Codex 0.164's `unified_exec` can't be turned off, so Codex is off unless the user accepts, under a warning, that it can read files (empty folder, read-only sandbox, no internet); a read can happen before Funes stops the run, and the provider sees it |
| T36 | Text the user removed from a memory survives the edit (v0.5) | Earlier versions are kept 90 days and at most 50 per memory, never shared, exported, sent to the iPhone or to a model provider; **Forget Earlier Versions** per memory; a switch in Settings ▸ Data turns them off and deletes them; purged with the memory and by Delete Now. Daily backups (7 days) hold older copies regardless, as before |
| T35 | Text sent through a subscription is kept or used for training under the user's consumer account terms (v0.3) | Only if the user chose a subscription provider; the disclosure line says the plan's training setting applies and links to it; the cloud limit and secret scanner apply as for any cloud provider. Funes never handles the plan's credentials ([ADR-0024](decisions/0024-subscription-providers.md)) |
| T37 | A search answer misstates a fact, or a memory's text steers it (v0.6) | Every claim must quote text that was sent for a memory it cites, checked by code, and the quote is shown under the claim; a claim with any failed quote is dropped and counted on the card. The results stay visible under the card, and a claim's number opens the memory with the quote highlighted. Memory text is fenced and labelled as data; the model only returns claims and can't act (no tools; subscription CLIs run isolated, T34). Spike F gates correct claims and the right "no answer" before it ships ([ADR-0028](decisions/0028-search-answers.md)) |
| T19 | A user approves without reading | Arming delay; the exact text is shown; per-memory checkboxes; sensitivity badges; no "always allow everything" button |
| T20 | Clock manipulation affects expiry | Expiry uses the Mac's clock (trusted, same user). Companion replay checks use ±120 s and the nonce cache |
| T23 | Public tunnel exposure of the Remote Access listener: scanning, guessing, flooding | Off by default, with a confirmation; per-agent **Allow cloud access**, off by default; a 128-bit secret path, so other paths get 404 before `Host` or a credential is read; `Host` allowlist (421); 256-bit credentials; a lockout per forwarded address (more than 30 failures a minute: 429 for 5 min) that never blocks a well-formed credential; the same per-agent rate limits, plus EK Bridge's stricter remote buckets (60 calls and 10 writes a minute); **Turn Off Remote Access** in the menu, a menu bar indicator, optional automatic turn-off. Residual: forwarded addresses can be spoofed, and a flood can occupy the port's 32 connections while it's on |
| T24 | OAuth consent phishing or spam: a look-alike app, or an attacker starting sign-ins | Nothing is fetched or shown unless the user opened a 10-minute pairing window from one agent. The browser and the Mac show the same six-digit code; the panel names the agent, the app (as reported), its metadata URL and the return host; **Allow** arms after 1 s; a new request never replaces an open panel; at most 3 wait. Exact redirect URIs, PKCE S256, `state` and `iss`; one app per window. Residual: a user who allows without comparing codes connects the wrong app, which gets only that agent's access, until **Revoke** |
| T25 | A remote credential is stolen: from the vendor that stores the remote token, or a cloud app's refresh token | Remote and local credentials are separate (a local key is refused remotely, a remote one locally). Digests only, in 0600 files that fail closed. Access tokens last 1 h and are bound to the MCP URL; refresh tokens rotate, and reusing a rotated one revokes the connection; codes are single use. Reset token, Revoke app, Reset Path… or turning cloud access off ends them at once, including remote calls already in progress, which release and save nothing. **Copy Remote Token…** asks first and clears the clipboard after 90 s. The secret scanner knows the `fns_mcpr_v1_`, `fns_oat_v1_`, `fns_ort_v1_` and `fns_ocs_v1_` prefixes. Residual: a vendor breach works until the user resets, and only within that agent's access |
| T26 | SSRF through the client-metadata (CIMD) fetch | Fetched only during pairing; `https` with a DNS name only (no IP literals); every resolved address must be public, and the connected address is checked again before any bytes go out; TLS verified for the name; no proxies, no redirects, 16 KB, 5 s, cached an hour; the document must name its own URL; no credential is sent (EK Bridge's T22) |
| T27 | Released text goes to the cloud vendor's servers and logs | Same as T1 and guarantee 9: only what the agent's access allows, with the same approvals. The Cloud section and Remote Access page say where text goes, and suggest one agent per cloud app with only the access it needs |
| T28 | Unattended cloud agents ask while the user is away | The same policy as locally: with Ask before sharing or saving on, requests wait 45 s, then 15 min in Pending requests, then expire. No remote auto-approval exists; the per-agent switches are the only way to skip panels, on every channel |
| T29 | A tunnel pointed at the local port 47625 | The local port refuses tunnel and forwarding headers (403) and non-loopback `Host` (421), and remote credentials don't work there. A proxy that rewrites `Host` and strips the headers is deliberate circumvention; the guided setup only offers 47627 |
| T30 | Spoofed tunnel status on the Mac, or a new tunnel tested while switching | Tunnel checks are read-only and display only: they never change what the server accepts. A tunnel being tested passes `Host` for the health route only. The health route answers only a nonce Funes issued in the last 30 s, once |

## 4. Privacy guarantees (each one is tested)
1. **No text before consent.** A request that needs approval returns no memory text, ids or titles. Only the profile fields the user shares with that agent go before approval, by the user's choice in its access (v0.5, [ADR-0026](decisions/0026-about-you-profile.md)).
2. **Exact and partial approval.** Only the memories the user ticks are released, with the exact text shown.
3. **Single use, short-lived, invalidated by change** (15 minutes; agent revision; memory version).
4. **Purpose can't change decisions.**
5. **Fail closed** for unknown, paused, expired or removed agents and for an unanswered panel.
6. **Logs hold ids and labels, never text.**
7. **Secrets are never stored.**
8. **Exports never contain keys, devices or access settings. Imports never grant access.**
9. **Revocation is immediate,** for future access. Text already released is beyond the vault's control, and the UI says so.
10. **The vault exists only on the Mac.** The iPhone holds only queued captures, plus the counts of [ADR-0025](decisions/0025-vault-overview-and-iphone-cache.md) and the name Funes calls the user ([ADR-0026](decisions/0026-about-you-profile.md)).
11. **AI processing is local by default.** Text reaches a non-local model provider only if the user chose one, never above the cloud sensitivity limit, and never when it matches the secret scanner.
12. **The same policy on every channel.** For the same agent and request, a call through Remote Access gets the same decision, panels and waits as a local call ([ADR-0018](decisions/0018-remote-access-in-v0.1.md)). Remote Access is off by default.

## 5. Everything that can leave the Mac
| Data | Destination | When |
|---|---|---|
| Memory text released to an agent | The agent, then its AI provider | Only on ALLOW or the user's approval |
| The profile fields shared with an agent (v0.5: name, pronouns, languages, location, time zone, occupation; each off unless the user turns it on for that agent, except the name) | The agent, then its AI provider (through the tunnel, for a cloud agent) | With every `request_memory` answer that passes the agent gate ([ADR-0026](decisions/0026-about-you-profile.md)) |
| Memory text released to a cloud agent, and its other tool results | The user's tunnel (its provider can read it if TLS ends at its edge: Cloudflare, ngrok; not Tailscale Funnel), then the cloud agent's vendor | Same, while Remote Access is on and the agent has cloud access |
| One HTTPS GET of a cloud app's client metadata document | The URL the app gives (public addresses only), with no credential | Only while a pairing window is open |
| One HTTPS request to Funes's own health URL | Through the user's tunnel, back to this Mac | When the guided setup or **Test** checks the tunnel |
| A `Doorbell` record holding only a random per-device `tag`, under a fresh random record name: no memory text, titles, task, agent name, counts or request id (v0.2) | The user's own private CloudKit database (`iCloud.com.funesvault`), which makes Apple's push service wake the iPhone ([ADR-0019](decisions/0019-cloudkit-doorbell-for-iphone-approvals.md)). The phone then fetches the panel from the Mac over the companion channel | When a Share, Save or access request starts waiting, iPhone access is on, and a paired iPhone has approvals on and has subscribed. Deleted when the request is answered, expires or is invalidated, and at launch |
| Update check (app version, OS version, as Sparkle sends) | GitHub Releases | Daily, if automatic checks are on |
| Companion responses (encrypted) | The paired iPhone, possibly through a tunnel | When the phone asks |
| Memory text (up to the cloud limit), search queries and agents' task text | The **embedding** provider the user chose, if it isn't on the device (v0.3, as a second index; v0.1 and v0.2 embed on the Mac with the bundled model only, [ADR-0016](decisions/0016-bundled-bge-small-embeddings.md), [ADR-0023](decisions/0023-provider-embeddings-second-index.md)) | Only after the user picks it; the disclosure is shown in Settings |
| Capture text (up to the cloud limit, after an on-device pre-screen); from v0.3 also agent suggestions and writes, imports and seed answers, plus related existing memories with their dates | The **classification** provider the user chose (**New memories** from v0.3), if it isn't on the device; from v0.3 this can be the user's Claude or ChatGPT plan, through their own Claude Code or Codex | Same |
| Clusters of related memories (up to the cloud limit) | The **daily tidy-up** provider (v0.3) | Same, and only while the tidy-up is on |
| The search text, and the titles, dates and bodies or best passages of a search's top 8 results (up to the cloud limit) | The **Search answers** provider (v0.6), if it isn't on the device | Only when the user asks (⌘⏎ or Ask Funes, on the Mac or a paired iPhone), and only while Search answers is on ([ADR-0028](decisions/0028-search-answers.md)) |
| Nothing else | — | No analytics, no crash reporting, no accounts |

**App Store privacy label (iPhone):** "Data Not Collected". The phone sends data only to the user's own Mac.

## 6. Known limitations (stated in the README and Security docs)
- **No protection against malware running as you.** Another program running as you can read the vault and key files. This is the same as EK Bridge and most Mac apps without the sandbox.
- **No control after release.** Funes can't recall or control text after it's released to an agent.
- **FileVault protects the data at rest.** Funes doesn't add its own database encryption in v0.1.
- **Some metadata is visible on the network.** On the LAN and Tailscale, which device is talking, when, and how much is visible, though not what.
- **Remote Access is experimental.** While it's on, the vault answers on a public address, and the tunnel provider may read the traffic (unless TLS ends on the Mac, as with Tailscale Funnel). Cloud agents need the Mac awake, online and running Funes.
